# S-OP-006 · Personal email and outreach do not happen

> *"I'm having a really hard time doing emails and personal outreach that so I
> want that to be automated by the hive using our systems. we need to give you
> email access and let you start sonnet now and stuff."*

**what_failed** — Outreach — the one activity that is upstream of every dollar
in the estate — does not get done. This is not a capability gap; it is a
completion gap. The operator can build a multi-substrate agent swarm and cannot
send the emails.

**mechanism** — ⚠️ **UNDER-SPECIFIED. The operator named the difficulty, not its
cause, and I will not assign one.** What can be recorded without inventing:

- The bottleneck is **structurally single-threaded**: every world-effect gate
  (send, publish, spend) is operator-only, correctly, so 100% of outreach
  volume queues at one human.
- The swarm currently **increases** the load on that gate rather than reducing
  it, because agents produce recommendations (which require a decision) rather
  than queued one-click artifacts (which require only a click).
- The observable signature: *"message every prior paying client, 30 minutes"*
  has been the #1 recommendation in HFO canon across **two consecutive
  documents** and has not been executed. That is data about the mechanism —
  **ranking is not the constraint, and re-ranking it a third time will not move
  it.**

**cost** — $0 external income over 18 months, 0 external receipts, against an
estate with two live public URLs and a prior paying client. 44 companies
enriched with **0 named human contacts** — outreach that stopped one step before
the step that requires a person.

**cure** —
1. **Change what the swarm produces from recommendations to one-click
   artifacts.** A drafted message with a named recipient and a send button is a
   click; a ranked list is a decision. Only the first reduces load.
2. **Budget the operator's clicks explicitly and make agents compete to consume
   fewer of them** — the fitness function is income per operator-click, not
   income. An agent that queues 40 items and burns 8 clicks loses to one that
   queues 2 and burns 1.
3. **Email access is a real, separable ask and it is gated on the operator.** It
   is a credential decision, not an agent decision. **Sigrún cannot and does not
   provision it.** The honest next step is: operator creates a dedicated sending
   identity, agents draft into it, sends stay operator-clicked.

**evidence** — operator verbatim, 2026-08-01 · `cap-0018` ($0 / 18 months / 0
external receipts, gen-132 capability ledger) · the "44 companies, 0 named
humans" defect recorded in `SIGRUN_SPATIAL_GESTURE_SWARM_INCOME_CASE_STUDIES_20260801.md`
§8.1.
