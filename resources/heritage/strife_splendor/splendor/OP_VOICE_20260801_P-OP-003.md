# P-OP-003 · Manual launch of tens-to-hundreds of agents works

> *"I can manually launch tens and hundreds of agents but they're not
> durable."*

**what_worked** — The operator can, by hand, bring up agent populations two
orders of magnitude larger than anything the automated system sustains.

**mechanism** — Launching is a **fan-out** operation with no state to maintain:
each agent is independently startable, and the operator's role is a repeated
identical action across substrates. Durability is a **fan-in** problem — it
requires shared state, a write path, and an exit condition — and every one of
those is currently broken or missing ([[S-OP-004]]).

> **Recorded precisely because the two halves point in opposite directions:**
> the *scaling* constraint is solved and the *persistence* constraint is not.
> Adding more agents is therefore not the lever; nothing is gained by fanning
> out further into a system that cannot fan in. **This row is evidence against
> "launch more agents" as a next move**, which makes it more useful as a
> splendor row than a flattering one would be.

**evidence** — operator attestation, 2026-08-01. Corroborating structure:
`SUBSTRATE_ROSTER.md` v0_2 §3.5 records 15 hourly ChatGPT-cloud agents
existing but **UNROSTERED** (⛔ B4) — i.e. launched, running, and not integrated.
That is exactly the shape the operator describes.

**bar_not_met** — ⚠️ does not meet the §2 splendor bar. No external effect, no
consumer. Admitted `PARTIAL` rather than by softening the bar.

**PARTIAL_ADMISSION: needs_operator_amplification_for_evidence** — a count, a
substrate, and a date for the largest population actually launched would turn
this from attestation into a measurement, and would set the baseline the
durability work has to beat.
