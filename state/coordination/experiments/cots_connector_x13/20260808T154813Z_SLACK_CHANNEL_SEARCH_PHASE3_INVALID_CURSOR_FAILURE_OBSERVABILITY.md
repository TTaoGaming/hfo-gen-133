# X13 Slack channel search — Phase 3 invalid-cursor failure-observability probe

One bounded read-only `slack_search_channels` call used the exact Git-persisted synthetic invalid cursor and was not retried. The connector returned only `execution_failed: internal_error`; it did not expose `invalid_cursor`, an HTTP status, provider request ID, rate-limit headers, native method identity, or effective permission/scope details. No channel data was returned or persisted, and no Slack mutation/message/file read occurred.

This is a measured failure-observability gap, not proof of a Slack provider-side `internal_error`. Slack's official cursor-pagination documentation says invalid/gibberish/stale cursors can produce `invalid_cursor`, and `assistant.search.context` explicitly lists `invalid_cursor` among its method errors. Because the connector's native mapping is still hidden, the safest interpretation is narrower: **this wrapper does not currently preserve a provider-specific cursor failure signal for this synthetic probe**.
