# X13 current campaign

The Google Drive read-only connector campaign is active at phase 2 of 4.

A bounded exact-name metadata search located one Drive item whose title had already been externalized in Slack as a heritage-only pointer. The search used explicit document mode and `best_effort_fetch=false`; no file body was returned or fetched.

The material defect is that metadata-only mode still exposed stable file and parent-folder pointers. Raw Drive identifiers were not persisted; only hashes were recorded in the immutable event. Treat this surface as sensitive metadata, not privacy-neutral metadata. Exact title equality supports location or pointer reconciliation only and does not establish byte identity, freshness, canonicality, current-state status, or uniqueness.

Live OAuth identity, scope, token type, credential custody, raw request count, quota-unit consumption, project quota class, fields mask, headers, retries, and connector internal call sequence remain hidden. Phase 3 should run one synthetic privacy-safe failure, permission, or connector-variance probe without content fetch.
