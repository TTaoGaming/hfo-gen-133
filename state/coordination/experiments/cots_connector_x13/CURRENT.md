# X13 current campaign

The Google Drive read-only connector campaign is active at phase 3 of 4.

A synthetic invalid page token produced `INVALID_ARGUMENT` / HTTP 400 at the `pageToken` parameter. The call failed closed with no result, identity-bearing metadata, or content, and no retry was observed. Google documents that rejected page tokens should be discarded and pagination restarted from the first page. The HFO gate is stricter: restart the same bounded query at most once and privately deduplicate by stable file ID.

The failure trace exposed the provider request contract for this invocation: Drive v3 `files.list`, `corpora=allDrives`, shared-drive support, a broad document MIME allowlist, page size 1, and an explicit metadata field mask. It also exposed two material defects. The error surface echoed the full provider request URL, so private query terms could leak into logs unless sanitized. The field mask omitted `incompleteSearch` while using `allDrives`; therefore empty or partial results cannot support complete-search or global-absence claims.

Raw request URLs and Drive identifiers were not persisted. Live OAuth identity, scope, token type, credential custody, quota headers, retry control, and wrapper internal call sequence remain hidden. Phase 4 must decide whether the bounded read-only surface is adoptable with these gates or should be deferred.
