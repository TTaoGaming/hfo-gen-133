# X13 Phase 4 Decision — GitHub recent PR intake

Decision: **ADOPT_WITH_GATES**.

Frozen evidence supports only a narrow use of the existing GitHub connector: bounded, read-only recent-PR intake for HFO review/preflight where retrieval of PR body text is acceptable. Phase 1 and Phase 2 both returned five matching PR numbers with matching open/draft/merged aggregates, and Phase 4 made no additional candidate call.

A material data-minimization gate remains. Both successful calls returned full PR body text even with diffs and comments disabled, so this connector must be treated as body-hydrating and must not be used where metadata-only retrieval or body non-disclosure is required. X13 receipts must continue to persist aggregates/digests only, not PR body or comment text.

The Phase 3 nonexistent-repository probe failed closed with a structured GitHub Search `422 Validation Failed` error and no observed retry, fallback, or mutation. Its detail conflates resource nonexistence with insufficient permission, so consumers must not infer authorization state from that error class.

Do not adopt authoritative PR inventory, stable-order claims, pagination semantics, explicit permission classification, rate-limit control, native query assumptions, or quota accounting. Measured operator minutes removed remain `0`; realized custom-code avoidance remains `0`; the `40–100 LOC` estimate is unvalidated. Adoption credit is `1`; fitness credit remains `0` until a named consumer demonstrates measured downstream value.
