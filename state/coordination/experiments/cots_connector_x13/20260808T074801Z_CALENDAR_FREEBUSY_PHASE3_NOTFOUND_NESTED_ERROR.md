# X13 Calendar FreeBusy Phase 3

A bounded synthetic nonexistent/inaccessible-calendar probe returned a successful connector envelope containing `busy: []` plus one nested per-calendar error: `domain=global`, `reason=notFound`. No retry, fallback, Calendar mutation, send, or event-detail fetch occurred.

This is a material connector behavior: **an empty busy array is not sufficient evidence that a calendar is free**. Consumers must inspect the per-calendar `errors[]` field first and fail closed for consequential scheduling.

Google's FreeBusy contract explicitly permits per-calendar errors including `notFound`. Google's Calendar error guide further states that `notFound` can mean either that the resource never existed or that the user cannot access the calendar. Therefore this probe does not distinguish nonexistent from inaccessible calendars and makes no authorization-completeness claim.

Phase 2 remains unresolved because the Phase-1 exact request preimage was not durable. Phase 4 must decide from the frozen evidence set without an additional Calendar candidate call.
