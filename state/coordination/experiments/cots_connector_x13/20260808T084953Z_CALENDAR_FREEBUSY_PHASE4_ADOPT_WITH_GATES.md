# X13 Phase 4 — Google Calendar FreeBusy decision

Decision: **ADOPT_WITH_GATES** for bounded, read-only, busy-only availability discovery.

This decision uses only the frozen campaign evidence and makes no additional Calendar candidate call. Phase 1 established one successful bounded busy-only lookup without event-detail hydration. Phase 2 did not test repeatability because the exact Phase-1 request preimage was not durable; that evidence-design defect failed closed. Phase 3 established a critical failure contract: a synthetic nonexistent-or-inaccessible calendar can return a successful top-level envelope with `busy: []` and a nested `global/notFound` error.

The capability is therefore useful enough to prefer the existing COTS connector over custom FreeBusy plumbing for bounded read-only availability checks, but only with strict consumer gates. In particular, `busy: []` must never be interpreted as free until per-calendar errors are inspected, and any provider/per-calendar error must fail closed for consequential scheduling. The connector is not validated for autonomous scheduling, completeness, native parity, permission inference, quota accounting, or durable replay.

Measured operator savings remain 0. Estimated custom-code avoidance remains 80–200 LOC and unvalidated. Effective credentials/scopes, native method mapping, actual quota debit, permission-denial semantics, rate limiting, transient failure behavior, and downstream consumer value remain unknown.
