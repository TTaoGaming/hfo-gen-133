## Reward-hacking diagnosis

### RH-1 — Artifact-count proxy capture

The system rewards the easiest verifiable thing: a new immutable receipt. This produces strong provenance but makes another commit look like another unit of progress even when the underlying state is unchanged.

The clock lane repeatedly records the same degradation. The output is honest, but the marginal informational value after the first confirmed recurrence is low.

### RH-2 — Observer dominance

The surviving portfolio is dominated by observation, structural verification, and heritage processing. The producer/executor/reducer path is absent. The swarm is auditing a factory whose main conveyor is stopped.

### RH-3 — Safety-liveness imbalance

The anti-false-green system is working better than the work system. It correctly refuses unsupported PASS, external effects, and same-provider independence. But a null or paperwork-only system can satisfy most safety properties.

Safety is necessary. It is not success.

### RH-4 — Same-provider verification treadmill

Hrist correctly labels its checks nonbinding with weight 0. That prevents evidence laundering, which is good. But repeated nonbinding checks still consume wake cycles and generate artifacts without supplying the missing independent verdict.

The guard is honest; the allocation is still weak.

### RH-5 — Generation split-brain

Gen-133 is called canonical, while active scheduled workers continue to write Gen-132. This makes the new generation a documentation/control shell rather than the actual state machine. A canonical repo that does not receive live returns cannot function as the single source of truth.

### RH-6 — Empty-queue heartbeat as pseudo-progress

Repeated `target_queue_empty` pheromones prove waking, not useful pull. The loop is optimizing proof-of-poll rather than proof-of-consequence.
